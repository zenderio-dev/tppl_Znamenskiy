# Выбор парадигмы и языка программирования

## Задача 1. Обработка больших данных в реальном времени

**Парадигма:** императивная + параллельное программирование

**Язык программирования:** C++ (OpenMP / CUDA)

**Обоснование:**

Один кадр весит 4096 × 4096 × 2 байта = 32 МБ, при 100 кадрах в секунду это около 3.2 ГБ/с, поэтому главное здесь — скорость.

- C++ компилируется в машинный код и работает быстро, в нём нет сборщика мусора, из-за которого бывают паузы.
- Память можно выделить заранее и переиспользовать буферы, поэтому потребление памяти стабильное, а это важно для работы 24/7.
- Проверку кадров легко распараллелить через OpenMP или CUDA, и для этого есть готовые библиотеки (OpenCV, FFTW).

Python для такого объёма данных слишком медленный.

## Задача 2. Прототип ML-сервиса для прогноза погодных условий

**Парадигма:** мультипарадигменная (скриптовая, с элементами ООП и функционального стиля)

**Язык программирования:** Python

**Обоснование:**

- На Python код пишется быстро, а в Jupyter удобно экспериментировать, так что MVP реально сделать за 2 недели.
- Есть все нужные ML-библиотеки: scikit-learn, XGBoost, PyTorch, pandas.
- У моделей в scikit-learn одинаковый интерфейс (`fit` / `predict`), поэтому алгоритмы легко менять.
- Прогноз делается раз в сутки, так что скорость языка здесь не важна.

## Задача 3. Интерактивный UI для торгового терминала

**Парадигма:** реактивная + функциональная

**Язык программирования:** TypeScript (React + RxJS)

**Обоснование:**

- Это веб-интерфейс, а TypeScript добавляет типизацию, которая помогает не запутаться в большом проекте.
- Данные из WebSocket, REST и от пользователя удобно представить как потоки RxJS и объединять их. Виджеты подписываются на общее состояние и обновляются сами, без прямых связей друг с другом.
- Компоненты и редьюсеры — это чистые функции, их легко тестировать (Jest).
- Уложиться в 16 мс помогают `React.memo`, неизменяемые данные и `throttle` частых обновлений.

## Задача 4. Прошивка для устройства регистрации температуры

**Парадигма:** процедурная (императивная)

**Язык программирования:** C

**Обоснование:**

- Код получается компактным, а память можно выделять статически, без `malloc`, поэтому он помещается в 256 KB Flash и 32 KB RAM.
- Есть прямой доступ к регистрам GPIO, ADC и UART через указатели с `volatile`.
- В C нет скрытых операций, поэтому время выполнения предсказуемо, что нужно для real-time.
- Спящие режимы и работа через прерывания помогают экономить батарею.
- Компиляторы C есть почти для всех микроконтроллеров, а аппаратную часть можно вынести в HAL, поэтому код переносимый.
